# План доработок сайта

Разбор состояния на 2026-08-15. Проверялось на собранной статике
(`npm run build` + `astro preview`) в headless-браузере: замеры контраста,
переполнение по горизонтали и переносы строк — не на глаз, а числами.

Ориентир для внешнего вида — реф интерфейса клиента (шесть вариантов темы:
тёмная панель, рамка в 1px, моноширинный текст, цвет как признак смысла).
Сайт и клиент должны выглядеть одной вещью. Пока сайт берёт из клиента только
палитру и шрифты, а строение — обычного тёмного лендинга.

## Сделано

Правки, которые не требовали решения автора.

| Что | Почему |
| --- | --- |
| Номера разделов `01/02/03`: `text-rule` → `text-ink-dim` | Цвет рамки на фоне окна даёт **2.27:1** при норме WCAG AA 4.5:1. Номера читались как грязь на экране. Сейчас 5.6:1 — весь текст страницы проходит AA. |
| В подвале `text-ink-dim/70` → `text-ink-dim` | 3.6:1 на 12px. Прозрачность здесь ничего не давала, кроме нечитаемой строки. |
| Блок характеристик — панель в обводке | Главная точка сходства с рефом: в клиенте так выглядит блок характеристик. Заодно чинит перенос: `max-w-[62ch]` на моноширинном элементе — это **не** 62 знака текста рядом. `ch` считается по шрифту самого элемента, Iosevka узкая, выходило ~434px вместо ~600px, и «upstream, unmodified» ломалось посреди строки. Ширина задана в rem, проверено на 360–1600px: переносов нет. |
| Скриншоты кликаются и открывают вариант 1600px | В сетке снимок 472px шириной, а интерфейс игры текстовый. Главный вопрос проекта — «видно ли не хуже, чем в оригинале» — на превью не проверить, а именно за этим на сайт и приходят. Ссылка, а не лайтбокс: на сайте один скрипт, второй ради этого не нужен. |
| `preload` для Manrope | Заголовок первого экрана набран Manrope, то есть шрифт участвует в LCP. Без preload браузер узнаёт о нём только разобрав CSS. Хеш в `href` совпадает с тем, что в `@font-face` — файл качается один раз (проверено в `dist/`). |
| Страница `404.astro` | GitHub Pages отдаёт `404.html` из корня сайта. Без него на любой опечатке показывалась бы чужая страница GitHub. |
| `aria-current="page"` в меню | Текущий пункт ничем не отличался — ни для скринридера, ни глазом. |
| `og:site_name`, `og:locale`, `og:image:alt`, размеры картинки | Минимум, который читают шреперы соцсетей. |
| Запасная картинка внутри `<video>`, явные `width`/`height` | Если не проиграется ни webm, ни mp4 — останется кадр, а не пустая рамка. |

## Осталось

### 1. Содержание — важнее всего остального

- [ ] **Кнопка GitHub на первом экране ведёт в репозиторий сайта, а не клиента.**
      Человек, пришедший по ссылке, жмёт её первой и попадает в исходники
      лендинга. Нужен репозиторий клиента (или явная подпись, что клиент пока
      не открыт). Правится в `src/config.ts`.
- [ ] **Нет ответа на вопрос «как попробовать».** Ни релизов, ни страницы
      загрузок, ни строки «пока не собрано». Для проекта в разработке честный
      ответ «сборок пока нет, следите за devlog» лучше, чем молчание.
- [ ] **Devlog — заглушка.** Content collection, посты в markdown,
      `/devlog/[slug]`, RSS.
- [ ] **Русский «Инвентарь (F2)» на `screen__01` и `screen__05`** — противоречит
      правилу style-guide про английский интерфейс. Переснять до показа сайта.
      (Уже отмечено в README.)

### 2. Ближе к рефу

- [ ] **Подписи внутрь рамки.** В клиенте у каждой панели есть заголовок —
      «Map», «Quick cast (Ctrl+1-9)», «At hand (F1)». На сайте рамка есть,
      а подпись висит под ней отдельной строкой. Перенести `figcaption` внутрь
      панели строкой-подвалом на `bg-panel` — и снимки станут читаться как
      панели интерфейса, а не как картинки в рамке.
- [ ] **Палитра простаивает.** Объявлены `hp`, `mp`, `damage`, `warning`,
      `magic`, `name`, `rare` — на странице живут только `ink`, `ink-dim`,
      `rule`, `panel`, `window` (плюс `name` на ховере логотипа и `warning`
      на 404). В клиенте цвет несёт смысл, и это стоит показать хотя бы в одной
      осмысленной точке — например, `status: in development` цветом
      предупреждения. Одна-две точки, не больше: раскрашенный лендинг будет
      имитацией, а не сходством.
- [ ] **Правая половина десктопа пустая.** Текст идёт колонкой 62ch, контейнер
      `max-w-5xl`, справа ничего. Реф — плотный интерфейс, где занят каждый
      угол. Либо осознанно оставить (обычная editorial-вёрстка, тоже честно),
      либо занять правую колонку чем-то полезным. **Решение за автором.**
- [ ] **Сетка скриншотов не разобрана по смыслу.** Три снимка из пяти — про
      камеру, один — панель описания монстра. Стоит разделить «мир» и
      «интерфейс»: второе и есть предмет проекта.

### 3. Техника

- [ ] **`npm run check` не работает** — требует `@astrojs/check` и `typescript`,
      их нет в devDependencies. Скрипт есть, а команда предлагает доустановить
      пакеты. Либо добавить зависимости, либо убрать скрипт.
- [ ] **Нет `sitemap.xml` и `robots.txt`.** `@astrojs/sitemap` + файл в
      `public/`. Две страницы обойдутся и без этого, но с devlog станет нужно.
- [ ] **`og:image` — webp 1440×822.** Стандарт карточки — 1200×630, и webp
      понимают не все шреперы (Telegram, часть RSS-читалок). Сделать отдельную
      карточку png/jpg, добавить генерацию в `scripts/build-media.mjs`.
- [ ] **Соотношение сторон героя зашито в компоненте** (`aspect-[1440/822]`),
      а размеры скриншотов идут из `shots.json`. Пережали видео из другого
      исходника — рамка молча поедет. Положить размеры героя в тот же манифест.
- [ ] **`prefers-reduced-motion` обрабатывается скриптом постфактум:** в разметке
      стоит `autoplay`, скрипт снимает атрибут и ставит паузу. На практике
      успевает, но конструкция хрупкая — надёжнее не ставить `autoplay` вовсе,
      а включать проигрывание из скрипта тем, кто не просил тишины.
- [ ] **`astro check` в CI.** Сейчас workflow гоняет только `npm run build`.

### 4. Проверено, менять нечего

- Переполнения по горизонтали нет ни на одной ширине от 360px.
- Весь видимый текст проходит WCAG AA по контрасту (минимум — 5.6:1).
- Шрифты уже подрезаны: 20 и 22 КБ, оба локальные, внешних запросов ноль.
- `width`/`height` стоят у всех картинок, вёрстку при загрузке не дёргает.
- `srcset`/`sizes` посчитаны верно под реальные ширины контейнера.
- Видео вместо гифки — 522 КБ против 74 МБ, решение правильное.
