# План доработок сайта

Разбор состояния на 2026-08-15. Проверялось на собранной статике
(`npm run build` + `astro preview`) в headless-браузере: замеры контраста,
переполнение по горизонтали и переносы строк — не на глаз, а числами.

Ориентир для внешнего вида — реф интерфейса клиента (шесть вариантов темы:
тёмная панель, рамка в 1px, моноширинный текст, цвет как признак смысла).
Сайт и клиент должны выглядеть одной вещью. Пока сайт берёт из клиента только
палитру и шрифты, а строение — обычного тёмного лендинга.

---

## Сделано

Правки, которые не требовали решения автора.

| Что | Почему |
| --- | --- |
| Номера разделов `01/02/03`: `text-rule` → `text-ink-dim` | Цвет рамки на фоне окна даёт **2.27:1** при норме WCAG AA 4.5:1. Номера читались как грязь на экране. Сейчас 5.6:1 — весь текст страницы проходит AA. |
| В подвале `text-ink-dim/70` → `text-ink-dim` | 3.6:1 на 12px. Прозрачность здесь ничего не давала, кроме нечитаемой строки. |
| Блок характеристик — панель в обводке | Главная точка сходства с рефом: в клиенте так выглядит блок характеристик. Заодно чинит перенос: `max-w-[62ch]` на моноширинном элементе — это **не** 62 знака текста рядом. `ch` считается по шрифту самого элемента, Iosevka узкая, выходило ~434px вместо ~600px, и «upstream, unmodified» ломалось посреди строки. Ширина задана в rem, проверено на 360–1600px: переносов нет. |
| Скриншоты кликаются и открывают вариант 1600px | В сетке снимок 472px шириной, а интерфейс игры текстовый. Главный вопрос проекта — «видно ли не хуже, чем в оригинале» — на превью не проверить, а именно за этим на сайт и приходят. Ссылка, а не лайтбокс: на сайте один скрипт, второй ради этого не нужен. |
| `preload` для Manrope | Заголовок первого экрана набран Manrope, то есть шрифт участвует в LCP. Без preload браузер узнаёт о нём только разобрав CSS. Хеш в `href` совпадает с тем, что в `@font-face` — файл качается один раз (проверено в `dist/`). |
| Страница `404.astro` | GitHub Pages отдаёт `404.html` из корня сайта. Без него на любой опечатке показывалась бы чужая страница GitHub. |
| `aria-current="page"` в меню | Текущий пункт ничем не отличался — ни для скринридера, ни глазом. |
| `og:site_name`, `og:locale`, `og:image:alt`, размеры картинки | Минимум, который читают шреперы соцсетей. |
| Запасная картинка внутри `<video>`, явные `width`/`height` | Если не проиграется ни webm, ни mp4 — останется кадр, а не пустая рамка. |

## Осталось

### 1. Содержание — важнее всего остального

- [x] **Кнопка GitHub вела в репозиторий сайта, а не клиента.** Убрана с первого
      экрана: мёртвая кнопка с подписью «позже» заставляет кликнуть, чтобы
      узнать, что кликать не надо. Вместо неё строки `client source — not public
      yet` и `builds — none yet` в блоке характеристик. Ссылка на исходники
      сайта осталась в подвале и там подписана. Вернуть кнопку — когда откроется
      репозиторий клиента, места помечены комментариями.
- [x] **Нет ответа на вопрос «как попробовать».** Закрыто там же: `builds — none
      yet` и есть ответ.
- [x] **Devlog.** Content collection, посты в markdown, `/devlog/[slug]`, RSS,
      черновики видны только на localhost.
- [ ] **Русский «Инвентарь (F2)» на `screen__01` и `screen__05`** — противоречит
      правилу style-guide про английский интерфейс. Теперь виден ещё и в
      og-карточке, то есть в превью ссылки. Переснять до показа сайта.

### 2. Ближе к рефу

- [x] **Подписи внутрь рамки.** Сделано, но подпись поставлена **сверху**, а не
      подвалом: в клиенте заголовки панелей («Map», «Spells (F11)») стоят над
      содержимым. Вёрстка одной панели вынесена в `components/Shot.astro`.
      Подсветка рамки — через `:has(a:hover)`, чтобы реагировать на наведение
      по снимку, а не по подписи.
- [x] **Палитра простаивает.** Раскрашены две строки, противоположные по
      смыслу: `game logic — upstream, unmodified` зелёным (HP) и `status — in
      development` оранжевым (предупреждение). Что незыблемо и что в движении —
      тезис про асимметрию вклада, сказанный цветом. Больше двух точек не
      добавлять.
- [ ] **Правая половина десктопа пустая.** — **отложено решением автора**,
      текущая editorial-вёрстка устраивает. Если возвращаться: в клиенте справа
      постоянная панель с характеристиками, и блок характеристик можно увести
      туда на широких экранах. Это перекличка со строением клиента, а не
      имитация.
- [ ] **Сетка скриншотов не разобрана по смыслу.** — **отложено**: текущие пять
      снимков тестовые, будут новые. Что снимать, по убыванию пользы:
      1. сравнение с оригиналом (webtiles и 3D в одной позиции) — единственный
         кадр, отвечающий на главный вопрос проекта;
      2. плотная схватка: несколько монстров, статусы, HP в опасной зоне;
      3. слои знания: что видно, что помнишь, что не исследовано;
      4. прицеливание заклинанием — линия, дальность, задетые клетки;
      5. одна сцена двумя камерами.
      Технически: один персонаж на все кадры (сейчас Conjurer и Magician —
      читается как нарезка), английский интерфейс, курсор мыши убрать из кадра.
      Трейлер-гиф — про то же самое.

### 3. Техника — закрыт полностью

- [x] **`npm run check`** — добавлены `@astrojs/check` и `typescript`.
      Сейчас 0 ошибок / 0 предупреждений / 0 подсказок.
- [x] **`sitemap.xml` и `robots.txt`.** `@astrojs/sitemap` + `robots.txt.ts`:
      robots отдаётся страницей, а не лежит в `public/`, потому что адрес карты
      сайта обязан быть абсолютным — иначе его пришлось бы вписать руками и не
      забыть при смене домена.
- [x] **`og:image`** — отдельная карточка `og-card.jpg` 1200×630, 79 КБ.
      Кадр вписан по высоте и добит по бокам цветом фона окна: кроп срезал бы
      верхнюю и нижнюю панели, а это ровно то, что показывать и надо.
- [x] **Соотношение сторон героя** переехало в манифест. Заодно `shots.json`
      стал `media.json` вида `{ hero, shots }`.
- [x] **`prefers-reduced-motion`.** `autoplay` убран из разметки совсем,
      проигрывание включает скрипт тем, кто не просил тишины. Цена — без JS
      видео не стартует, но постер остаётся.
- [x] **`astro check` в CI** — отдельным шагом до сборки.
- [x] Попутно: `z` из `astro:content` в Astro 7 устарел, переведено на прямой
      импорт `zod` с явной зависимостью (транзитивная копия сломалась бы на
      pnpm или при смене зависимостей Astro).

### 4. Отложено осознанно — решения приняты, реализации нет

- [ ] **Поддержать проект (донат).** Подход зафиксирован, ждём выбора площадки
      (Boosty, Ko-fi, Patreon, GitHub Sponsors — последний требует публичного
      репозитория, он уже публичный). Две точки: `.github/FUNDING.yml` даёт
      кнопку Sponsor в шапке репозитория, на сайте — строка в подвале.
      **Ссылкой, а не виджетом:** iframe Ko-fi или Patreon тянет чужие скрипты
      и трекеры, и строчку «no trackers, no third-party requests» придётся
      снять. Для технической аудитории ссылка и честнее.
- [ ] **Обратная связь.** Пока обсуждать нечего: клиента ни у кого на руках
      нет, а замечания к сайту — это Issues уже открытого репозитория. Когда
      откроется репозиторий клиента, Issues там и станут каналом. Почту на
      странице не публиковать: `mailto` со статики собирают скраперы.
- [x] **Страница «о себе» — решено не делать.** Для сольного хобби-проекта она
      не отвечает ни на один вопрос посетителя. Нужное уже сказано: «hobby
      project» в тексте, `credits`, devlog.
- [x] **Дубль ссылки на devlog** (в шапке и кнопкой на первом экране) — убран.
      Первый экран остался без призыва к действию намеренно: пока скачивать
      нечего, это честнее, чем изобретать кнопке занятие. Ссылка переехала под
      блок характеристик, где после строки `builds — none yet` вопрос «где
      следить» и возникает.
- [x] **Дата последней записи devlog на лендинге.** Для проекта без релизов это
      единственное доказательство, что он жив: иначе неоткуда понять, вчера
      тут что-то было или два года назад.

### 5. Что бывает на таких страницах и чего здесь нет

Разобрано, чтобы не возвращаться к вопросу.

**Стоит сделать, когда появится содержание:**

- **«Что работает, что нет»** — короткий честный список состояния. Для проекта
  без релизов это самое ценное из недостающего: отвечает на вопрос «это правда
  работает или красивые картинки». Нужны факты от автора.
- **Требования и платформы** — вместе со страницей загрузок, не раньше.
- **Contributing** — когда откроется репозиторий клиента.

**Не нужно:**

- FAQ — вопросов пока никто не задал, выдуманный FAQ виден насквозь.
- Changelog — его роль играет devlog.
- Сравнение с оригиналом таблицей — решается одним скриншотом (см. п. 2).
- Подписка по почте, счётчики звёзд, отзывы, «нас выбирают» — для хобби-проекта
  на GitHub Pages это шум, и аудитория с r/dcss считывает его как маркетинг.

### 6. Проверено, менять нечего

- Переполнения по горизонтали нет ни на одной ширине от 360px.
- Весь видимый текст проходит WCAG AA по контрасту (минимум — 5.6:1).
- Шрифты уже подрезаны: 20 и 22 КБ, оба локальные, внешних запросов ноль.
- `width`/`height` стоят у всех картинок, вёрстку при загрузке не дёргает.
- `srcset`/`sizes` посчитаны верно под реальные ширины контейнера.
- Видео вместо гифки — 522 КБ против 74 МБ, решение правильное.
