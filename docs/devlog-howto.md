# Как добавить запись в devlog

Файл-инструкция для агента. Использование: **«Прочитай `docs/devlog-howto.md`
и оформи запись про то, что мы сегодня сделали: …»**

Всё, что нужно, есть здесь — отдельно читать README не обязательно.

---

## 1. Куда класть

```
src/content/devlog/<slug>.md     обычная текстовая запись
src/content/devlog/<slug>.mdx    если нужен клип
```

`.md` и `.mdx` лежат рядом и обрабатываются одинаково. Разница одна:
**в `.mdx` работают компоненты**, поэтому клип можно вставить только туда.
Картинки работают в обеих.

`<slug>` — латиница, строчные, слова через дефис. **Имя файла становится
адресом**: `render-distance.md` → `/devlog/render-distance/`.

Правила имени:

- дату в имя НЕ ставить: она во frontmatter, иначе полезет в адрес;
- имя должно пережить время: `fog-of-war` — хорошо, `update-3` — плохо;
- **менять имя после публикации нельзя** — адрес уже разослан и лежит в RSS.
  Ошиблись — оставьте как есть.

## 2. Frontmatter

Обязателен. Схема проверяется на сборке (`src/content.config.ts`), при ошибке
сборка падает с внятным сообщением — это норма, а не поломка.

```markdown
---
title: 'Fog of war and what it costs'
date: 2026-08-20
summary: 'Одно-два предложения. Попадает в список записей, в RSS и в og:description.'
draft: false
---
```

| поле | тип | обязательно | примечание |
| --- | --- | --- | --- |
| `title` | строка | да | без точки в конце |
| `date` | `YYYY-MM-DD` | да | без кавычек |
| `summary` | строка | да | 1–2 предложения, не пересказ целиком |
| `draft` | булево | нет, по умолчанию `false` | `true` — видно на localhost, не попадает ни в сборку, ни в RSS |

Заголовок первого уровня в тексте НЕ пишется — `title` уже отрисуется как `h1`.

## 3. Язык и тон

**Текст записи — английский.** Сайт переведён на четыре языка, но записи не
переводятся: это содержательные тексты, четыре версии каждой пришлось бы
держать в согласии вручную. На локализованных страницах devlog об этом
сказано прямо.

Не переводятся и не переиначиваются: названия из игры (`Foxfire`, `Dungeon:1`),
имена собственные (Unity, Astro, Iosevka), строки лицензий.

Тон — тот же, что на всём сайте:

- **сдержанно, без маркетинга.** Аудитория техническая, r/dcss. Слова вроде
  «amazing», «blazing fast», «game-changing» тут читаются как враньё;
- **числа измеренные, а не прикидочные.** «74 МБ → 522 КБ» работает, «намного
  меньше» — нет. Если числа нет — не выдумывать, а не писать;
- **об ошибках писать прямо.** Две существующие записи так и сделаны, это
  установившийся голос проекта, а не самобичевание. Разбор собственной
  ошибки — самый ценный тип записи для этой аудитории;
- **не обещать сроков.** «No schedule» написано на странице devlog.

## 4. Чего делать нельзя

Самое важное в этом файле.

- **Не выдумывать факты.** Если неизвестно, что именно сделано в клиенте, —
  спросить у автора, а не додумать правдоподобное. Выдуманный прогресс
  в devlog технический читатель считывает мгновенно, и доверия к остальному
  тексту после этого нет.
- **Не писать про сайт, если запись про клиент.** Devlog — про 3D-клиент.
  Две записи подряд про устройство сайта уже есть, третьей быть не должно.
- **Не переименовывать и не удалять опубликованные записи.**
- **Не трогать `src/i18n/ui.ts`** ради записи: обвязка devlog переведена,
  сами записи — нет.

## 5. Что умеет разметка

Стили заданы в `src/styles/global.css`, блок `.prose`.

| разметка | как отрисуется |
| --- | --- |
| `## Заголовок` | подзаголовок раздела (h2). Начинать с `##`, не с `#` |
| `### Подзаголовок` | уровнем ниже, использовать редко |
| `**жирный**` | Manrope 600 |
| `` `код` `` | моноширинный на фоне панели |
| ` ```блок``` ` | моноширинный блок, длинные строки прокручиваются внутри |
| таблица | **моноширинная** — она для замеров и сравнений |
| `> цитата` | вертикальная черта слева |
| список | маркеры цветом рамки |

Граница гарнитур несущая, а не стилевая (правило из `docs/style-guide.md`):
**моноширинным набрано машинное** — код, таблицы замеров, имена файлов, вывод
команд; **гротеском — наш текст**. Поэтому числа и файлы — в таблицу или в
`код`, а не в обычный абзац.

`**жирный**` вокруг `` `кода` `` жирным не станет: моноширинного полужирного
в проекте нет, а подделывать жирность браузеру запрещено (`font-synthesis-weight: none`).

## 6. Картинки

**Только относительным путём, рядом с записью.** Проверено на сборке.

```
src/content/devlog/
  fog-of-war.md
  fog-of-war-before.webp
  fog-of-war-after.webp
```

```markdown
![Что видно на снимке](./fog-of-war-before.webp)
```

Так Astro обработает файл сам: подставит `base`, добавит хеш к имени, проставит
настоящие `width`/`height` (без них картинка дёргает вёрстку) и `loading="lazy"`.

**Абсолютный путь НЕ работает.** `![](/media/foo.webp)` уедет в разметку как
есть, без префикса `/dcss-3d-website` — на живом сайте это 404, а локально
всё выглядит нормально. Классическая ловушка этого проекта.

Формат — `.webp`. Ширина 1600px хватает с запасом. Пережать:

```
ffmpeg -i исходник.png -vf "scale=1600:-2:flags=lanczos" -c:v libwebp -quality 78 выход.webp
```

`alt` — обязателен и осмысленный: описывать, **что на снимке видно**, а не
«скриншот игры».

## 7. Клипы

**Гифку прикладывать нельзя.** Гифка хранит каждый кадр целиком, видеокодек
кодирует только изменения — на записи интерфейса это разница в два порядка
(74 МБ против 0.5 МБ на первом экране). Первая запись этого devlog объясняет
переход на видео с числами; гифка следом противоречила бы ей публично.

Порядок:

**1.** Положить исходник записи экрана в `media-src/devlog/<имя>.<ext>`.
Принимаются `gif`, `mp4`, `mov`, `mkv`, `webm`, `avi` — то есть что угодно,
что выдаст программа записи. Имя латиницей через дефис, оно же станет именем
клипа в разметке.

**2.** Пережать:

```
npm run media
```

Получится три файла в `public/media/devlog/`: `.webm` (основной), `.mp4`
(Safari и старые устройства) и `-poster.webp` (первый кадр). Размеры
запишутся в `src/data/media.json` — руками их проставлять не нужно.

**3.** Запись должна быть **`.mdx`**, и внутри:

```mdx
<Clip
  name="fog-of-war"
  caption="fog of war — before the fix"
  label="The remembered part of the level fading out as the character moves away"
/>
```

| атрибут | обязателен | что это |
| --- | --- | --- |
| `name` | да | имя файла без расширения, как в `media-src/devlog/` |
| `label` | да | что происходит на записи; уходит в `aria-label` и в `alt` запасной картинки |
| `caption` | нет | подпись над клипом, как заголовок панели в клиенте |

Импортировать `Clip` не нужно — он подключён к странице записи.

Если имени нет в манифесте, сборка падает с внятным сообщением: значит забыли
`npm run media`.

**Исходники в репозиторий не едут** — `media-src/` в `.gitignore`, как и
исходники героя. Коммитятся только пережатые файлы из `public/media/devlog/`.
Оригинал записи держите у себя.

Клип должен быть **коротким**: 5–15 секунд, показывающих одну вещь. Клип на
минуту никто не досмотрит, а весить он будет как вся остальная страница.

## 8. Проверить перед публикацией

```
fnm use                 # если node не той версии
npm run check           # типы и разметка, должно быть 0 ошибок
npm run build           # запись должна появиться в списке маршрутов
npm run dev             # посмотреть глазами
```

Адрес локально — **с подпутём**: `http://127.0.0.1:4321/dcss-3d-website/devlog/<slug>/`
Корень `/` отдаёт 404, так и задумано.

Посмотреть глазами обязательно: в `dist/` запись должна появиться,
на лендинге — обновиться строка с датой последней записи, в `/devlog/` —
встать сверху списка.

> Если `npm` не найден: `fnm env --use-on-cd | Out-String | Invoke-Expression`.
> Если `npm install` падает с `ENOTFOUND` — добавить
> `--registry=https://registry.npmjs.org/` (в `~/.npmrc` корпоративное зеркало).

## 9. Опубликовать

```
git add src/content/devlog/
git status              # глазами: ничего лишнего
git commit -m "Devlog: <заголовок записи>"
git push
```

Пуш в `main` запускает сборку и публикацию, через пару минут запись на сайте.
Ход прогона — вкладка Actions. Кеш GitHub Pages — 10 минут.
